# 模板说明与执行边界

本目录固定保留五份 **illustrative reference（示意参考模板）**。它们从一套真实个人系统中抽象出数据结构和配置形状，但不是源代码、不是完整配置，也不能直接部署。

## 总原则

- JSON Schema 只执行标准关键字；所有 `x-*` 字段都是说明性扩展，普通校验器会忽略。
- SQL 只执行 DDL 中实际声明的列、主键、唯一约束和 `CHECK`。注释不会变成数据库行为。
- 环境变量文件只展示一种可解析的赋值格式；变量值是否可信、由谁设置、服务是否使用，仍由应用和启动器决定。
- 语法通过不等于治理机制成立。采用者必须补齐应用代码、身份认证、文件权限、失败策略、测试和运行监控。

## 五份文件分别约束什么

| 文件 | 格式本身能约束 | 必须由应用代码或运行环境约束 |
|---|---|---|
| `memory-metadata.schema.json` | 必填字段、类型、枚举、scope 字符串格式、数组最少项数 | 字段由服务端生成、owner 字段彼此一致、调用方不能覆盖、scope 不扩权、内容闸门、有效期语义、六道召回过滤、哈希与正文对应 |
| `review-queue.schema.json` | 顶层字段、固定版本值、条目类型、哈希字符串形状、候选分类枚举 | 文件缺失时 fail-closed、owner 与当前实例一致、计数与 `items` 对应、ID 去重、关系有效、理由不泄露正文、哈希来自当前正文、队列权限与留存 |
| `review-ledger.schema.sql` | 表、列、主键、幂等键唯一性，以及 DDL 中明确写出的状态/动作 `CHECK` | 外键关系、哈希真实性、事件只追加、覆盖层 UPSERT 规则、动作到生命周期映射、单事务应用、队列重验、文件安全打开、只读连接、权限收紧、批次大小 |
| `runtime-scopes.example.env` | POSIX shell 能解析引号和赋值；JSON 数组作为单个字符串传递 | owner 鉴权、变量来源可信、scope 规范化与子集检查、管理模式清理、客户端是否真的使用这些值、配置完整性、操作系统隔离 |
| `health-report.schema.json` | 必填维度、状态枚举和基础结构 | `overall_status` 等于最差维度、健康数据真实且新鲜、备份回执可信、恢复演练真实完成、删除策略真正执行、通知脱敏与精确路由 |

### 关于 `format`

这些 JSON Schema 使用 Draft 2020-12。`format: "date-time"` 是否作为断言执行，取决于所用校验器及其配置；不能只因为 schema 中写了 `format` 就认为时间戳一定被拒绝或接受。应用层仍应使用明确的时间解析和失败策略。

### 关于 `.env` 示例

`runtime-scopes.example.env` 明确采用 **POSIX shell assignment**：标量使用双引号，scope 使用 JSON array string，并以单引号包住整个 JSON 字符串。替换全部占位符后，文件可以由 `sh` / `bash` / `zsh` 读取，服务再对 scope 值做 JSON 数组解析；不要把带占位符的示例当作真实配置发布。

环境变量 scope 是应用治理策略，不是 macOS 用户、文件权限、sandbox 或容器级的安全边界。

## 基础校验范围

本仓库发布前只保留与文档仓库相称的基础检查：

- JSON 文件可解析，三个 schema 能通过 Draft 2020-12 元 schema 检查；
- SQL DDL 能在空 SQLite 数据库执行；
- 环境变量示例能通过 POSIX shell 语法检查；
- Markdown 相对链接存在，代码围栏与 Mermaid 围栏成对；
- 当前文件、可达 Git 历史和远端新 clone 接受通用秘密扫描与本机私有禁词检查；孤立对象与服务端缓存是否已清除要另行核验。

这些检查不构成端到端功能、安全性或可部署性证明。
